<a> vs <link>의 차이점과 개념에 대해서 그리고 추가적으로 애이태그는 매번 html문서를 다시 다운받지만 링크는 내가 이동하려는 페이지만 요청이 들어가게 된어 리소스를 덜 잡아 먹는 내용도 알게됨. 그리고 내가 링크 태그에 대해서 너무 헷갈려서 공부해본 결과 아주 작은 아이콘을 넣어 줄 때 사용한다고 함 보통 탭바 옆에 아이콘있는데 거기에 주로 넣어주는 것 

<a> (Anchor) 태그: 사용자가 마우스로 클릭해서 다른 페이지나 문서 내 특정 위치로 이동(하이퍼링크)할 때 사용하는 HTML 태그입니다.

<link> 태그: 화면에 누르는 링크를 만드는 것이 아니라, 브라우저가 웹페이지를 읽을 때 외부 파일(CSS 스타일시트, 아이콘 등)을 연결해 주는 통로 역할을 합니다.
rel 속성: 연결하려는 파일이 문서와 어떤 관계인지 브라우저에게 알려주는 규격이며, 표준 규격 이름(stylesheet, icon 등)을 반드시 사용해야 브라우저가 올바르게 인식합니다.
---
시맨틱 태그 (Semantic Tag)를 사용하는 이유
의미 부여: 단순한 화면 분할(<div>)을 넘어, 브라우저와 시스템에 코드의 '의미'를 전달합니다.

웹 접근성 향상: 스크린 리더 같은 보조 기기가 웹페이지의 구조(내비게이션, 본문 등)를 정확히 읽어 사용자에게 음성으로 안내할 수 있습니다.

검색 엔진 최적화 (SEO): 구글 같은 검색 엔진 봇이 중요 콘텐츠와 부가 정보를 쉽게 파악하여 검색 결과 노출에 유리해집니다.
---
<!DOCTYPE html> 선언문의 역할
최신 표준 모드 지시: 브라우저에게 이 문서는 최신 HTML5 표준 규격으로 작성되었으니 최신 엔진으로 해석하라고 명령하는 브라우저 지시어입니다.

호환 모드(Quirks Mode) 방지: 이 선언문이 없으면 브라우저가 옛날 방식의 호환 모드로 화면을 그려 레이아웃이 깨질 수 있습니다. 다시 말해, 다른 사람과의 버전 차이나 코드 충돌을 막아주는 기능은 아니며, "브라우저가 이 HTML 문서를 읽을 때 최신 표준 엔진을 사용해서 오차 없이 정확하게 그려라"라고 명령하는 브라우저 전용 설정 스위치라고 생각하시면 됩니다.
---
<head>는 웹사이트가 정상적으로 작동하기 위해 필요한 설정과 연결 정보(브라우저가 읽는 무대 뒤의 준비 작업)를 담당하고,

<body>는 사용자에게 실제로 보여지는 모든 콘텐츠와 화면(관객이 보는 무대 위)을 담당합니다.

script 태그
자바스크립트 파일을 연결하거나(<script src="app.js"></script>), 태그 안에 직접 자바스크립트 코드를 작성할 때 사용합니다.

link 태그
외부 리소스를 문서와 연결할 때 사용하는데, 가장 대표적인 용도가 CSS 파일 연결(<link rel="stylesheet" href="style.css">)입니다.
다만 link 태그가 CSS 전용은 아니에요. rel="icon"으로 파비콘을 연결하거나, rel="preload", rel="canonical" 등 다른 용도로도 쓰입니다. 그래도 실무에서는 CSS 연결 용도로 가장 많이 씁니다.

다른 페이지로 이동하는 링크를 만들 때는 <a href="...">
이 처럼 각자 파일의 종류에 따라 사용하는 태그가 다르다는 것을 알게 됨
---
<article>, <section>, <div>태그가 눈에는 똑같은 역할을 하는 것으로 보인다 하지만 그 자리에 div로 써도 아무런 차이가 없다면 그 자리는 원래 div를 쓰는게 맞고 태그를 통해서 의미 부여를 할 수 있으면 그 자리는 Semantic 태그를 쓰는 것이 맞다 그리고 둘의 차이점은 
section: 문서 안에서만 의미가 통하는 "주제 구획". 떼어내면 문맥이 사라짐. (예: 최근 게시글, 학력)
article: 혼자 떼어내도 완결되는 "독립 콘텐츠". (예: 블로그 글 하나, 뉴스 기사 하나)
구조: section(챕터) 안에 여러 개의 article(개별 항목)이 들어가는 경우가 많음.
판단법: "이것만 떼어서 다른 곳에 놔도 말이 되나?" → 되면 article, 안 되면 section.
